== Introduction

The RISC-V S-level Physical Memory Protection (SPMP) extension enables an S-mode operating system to isolate its U-mode tasks in environments where supervisor mode is implemented but virtual memory is not, as is common in the IoT and automotive domains, where an MMU is frequently avoided to comply with stringent constraints on system resources and execution latency. The same domains increasingly rely on virtualization to consolidate formerly distributed microcontrollers into fewer, more capable devices, such as the zone controllers of modern automotive E/E architectures, time-multiplexing real-time operating systems and mixed-criticality workloads on a single hart while preserving their isolation and worst-case execution time guarantees. Real-time hypervisors rely on two-stage memory protection for this purpose. One stage isolates virtual machines from each other, the other isolates the mixed-criticality tasks within each guest.

A guest operating system running in VS-mode has the same need for SPMP as when running natively, to isolate its VU-mode tasks. Without hardware support, the hypervisor must trap and emulate every guest access to the SPMP state, folding the guest's rules into the single SPMP alongside its own. Since the SPMP does not distinguish VS-mode from VU-mode accesses, treating both as U-mode accesses, the hypervisor would furthermore have to intercept every transition between VS-mode and VU-mode and reprogram the SPMP accordingly. This adds complexity to the hypervisor, and it adds latency and jitter to the guest's task context switches, at odds with the real-time guarantees the guest, often an RTOS, is expected to provide.

The RISC-V S-level Physical Memory Protection for Hypervisor extensions address this by integrating the SPMP and Hypervisor extensions into a two-stage SPMP. The first stage is the virtual SPMP (vSPMP), under the control of VS-mode, which allows a guest supervisor to specify memory protection policies within its guest physical address space without hypervisor intervention. Guest VS/VU-mode accesses are further checked by the SPMP, as defined by the RISC-V S-level Physical Memory Protection (SPMP) specification, Version 1.0. The extensions replicate for VS-mode the SPMP support available to HS-mode, with as few changes as possible to the structure and functionality of the base extensions, and complement it with enhancements for the hypervisor, such as the delegation of hardware entries between the SPMP and the vSPMP and the separate control of the SPMP entries applied to guest accesses.
